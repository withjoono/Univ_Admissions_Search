# T검색 UI/UX 개선 기록 (2026-09-14)

## 화면 분석

- 배포 URL: https://search-front.firebaseapp.com/ — 제목, 검색창, 브라우저 기본 select 3개와 0건 표시가 전부인 화면을 확인했다. 로컬에 이미 추가된 브랜드·푸터 변경은 배포 화면과 달랐다.
- 탐색을 시작할 단서, 검색 조건의 계층, 빈 결과에서의 다음 행동이 부족했다.
- Hub 공통 디자인 토큰의 Pretendard 서체, 8/12/16px 모서리와 앱별 강조색 방식을 참고했다. T검색 기존 프로모의 청록색 #0f766e를 검색 화면에도 적용했다.
- 수시 olive·정시 orange는 공통 앱 테마에서 가져와 결과 배지에 반영했다. 로고와 생성된 공통 푸터는 유지했다.

## 적용 내용

1. 공통 헤더: T검색 브랜드, 전형 검색·서비스 소개·이용 가이드, T스쿨 이동. 프로모 화면도 동일 헤더를 사용한다.
2. 검색: 소개 문구와 가벼운 벡터 장식, 큰 검색창, 추천 키워드 버튼, 검색어 삭제.
3. 조건: 모집 시기·교육과정·지역, 적용 조건별 해제, 전체 초기화. Zustand의 부분 병합 때문에 기존 reset에 남던 조건도 제거한다.
4. 결과: 대학 → 학과 → 전형 정보 순서, 분리된 모집인원, 수시·정시 배지. 가짜 결과·가짜 통계는 제품 코드에 추가하지 않았다.
5. 상태: 로딩 skeleton / 결과 없음 / 연결 실패 / 재시도. 이전 조건의 결과 갱신 중에는 흐리게 표시하고 페이지 이동을 막는다. HTTP 요청은 12초 제한으로 무한 대기를 방지한다.
6. 모바일: 필터 접기, 한 열 결과, 긴 한글 제목 줄바꿈. 키보드 포커스, 입력 레이블, 상태 알림, 본문 바로가기, 동작 줄이기 설정을 지원한다.
7. 가이드: 구현된 검색·필터·결과 확인을 기준으로 설명을 수정하고 더 알아보기 카드에 실제 링크를 연결했다.

## 검증

- `npm run build --prefix search-frontend`: TypeScript + Vite 성공.
- 브라우저: 기본 데스크톱과 390×844 모바일 화면 확인.
- DB에 연결하지 않는 임시 loopback API로 결과 카드, 긴 학과명, 0명/미제공 구분, 다음 페이지, 수시+교육과정 필터, 초기화, 검색어 제출, 빈 결과를 검증했다. 검증 종료 후 해당 API를 종료했다. fixture는 제품 코드에 포함되지 않는다.
- 실제 로컬 API 연결 실패 화면과 재시도 UI를 확인했다. 실제 운영 검색 데이터의 정확성·가용성을 검증한 것은 아니다.
- 기존 미커밋 변경은 유지했다. DB 변경, push, 운영 배포는 하지 않았다.

## 남은 운영 확인

배포 화면의 0건 표시만으로 운영 데이터가 없다고 단정할 수 없다. 저장 문서는 백엔드 미배포로 기록되어 있으므로 실제 배포·API 상태는 별도 확인이 필요하다. 이번 작업은 디자인과 검색 UX 개선이며 백엔드 배포를 포함하지 않는다.
